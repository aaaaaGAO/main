## 二、散落函数问题分析

### 2.1 utils 目录下的散落函数

**问题描述**：utils 目录下存在多个散落的独立函数，这些函数被多个模块复用，但缺乏统一的组织。

**具体实例**：

| 文件 | 散落函数 | 用途 |
|------|---------|------|
| `utils/excel_io.py` | `norm_str()` | 字符串规范化 |
| `utils/excel_io.py` | `nfc_normalize()` | Unicode 规范化 |
| `utils/excel_io.py` | `split_input_lines()` | 解析输入行 |
| `utils/file_io.py` | `write_text_safe()` | 安全文件写入 |
| `utils/sheet_filter.py` | `parse_selected_sheets()` | 解析 sheet 勾选 |
| `utils/path_utils.py` | `get_base_dir()` | 获取基准目录 |

**改进建议**：

```python
# 方案1：将相关函数组织为 @staticmethod Class
class StringUtils:
    @staticmethod
    def norm_str(raw_value) -> str: ...
    @staticmethod
    def nfc_normalize(raw_text: str) -> str: ...
    @staticmethod
    def split_input_lines(text: str) -> List[Tuple[str, str]]: ...

class FileUtils:
    @staticmethod
    def write_text_safe(file_path: str, content, ...) -> None: ...

# 方案2：使用模块级函数（当前方案），但改进 __all__ 导出
# utils/__init__.py
from .excel_io import norm_str, nfc_normalize, split_input_lines
from .file_io import write_text_safe

__all__ = [
    "StringUtils",  # 如果用 Class
    "norm_str",     # 如果保留散落函数
    ...
]
```

### 2.2 相似功能的重复实现

**问题描述**：存在多个功能相似的函数，容易造成维护困难。

**具体实例**：

| 位置 | 函数名 | 功能 |
|------|--------|------|
| `core/common/sanitizer.py` | `sanitize_case_id()` | 用例 ID 清洗 |
| `core/common/name_sanitize.py` | `sanitize_clib_name()` | Clib 名称清洗 |
| `infra/excel/header.py` | `normalize_cell_text()` | 单元格值规范化 |
| `utils/excel_io.py` | `norm_str()` | 字符串规范化 |
| `generators/capl_soa/soa_excel_utils.py` | `normalize_cell_text()` | 单元格值规范化 |

**问题分析**：
- `sanitize_case_id` 和 `sanitize_clib_name` 功能有重叠（都是字符串清洗）
- `normalize_cell_text` 和 `norm_str` 功能几乎相同

**改进建议**：

```python
# 创建统一的字符串工具类
class StringSanitizer:
    """字符串清洗统一接口"""
    
    @staticmethod
    def normalize(value) -> str:
        """通用规范化：None 转空串，去首尾空白"""
        if value is None:
            return ""
        return str(value).strip()
    
    @staticmethod
    def sanitize_case_id(raw: Any) -> Tuple[str, bool, str]:
        """用例 ID 清洗"""
        ...
    
    @staticmethod
    def sanitize_clib_name(name: str) -> str:
        """Clib 名称清洗"""
        ...
```

## 三、常量定义方式分析

### 3.1 纯 Class 常量 vs @dataclass

**当前实现**：

```python
# 方式1：纯 Class（推荐用于常量）
class HttpStatus:
    OK = 200
    NOT_FOUND = 404

# 方式2：@dataclass（data_only=True 场景使用）
@dataclass
class FilterStats:
    filtered_by_level: int = 0
    filtered_by_platform: int = 0
```

**问题**：项目中同时存在两种写法，风格不统一。

**建议**：
- **纯常量**（如配置项、状态码）：使用纯 Class
- **数据结构容器**（如需要实例化存储数据）：使用 @dataclass

**方案 2：使用路由装饰器统一处理**

```python
# web/routes/decorators.py
from functools import wraps

def route_handler(f):
    """统一处理异常和响应"""
    @wraps(f)
    def wrapper(*args, **kwargs):
        try:
            result = f(*args, **kwargs)
            if isinstance(result, tuple) and len(result) == 2:
                body, status = result
                return jsonify(body), status
            return jsonify(result), 200
        except ValidationError as e:
            return jsonify({"success": False, "message": str(e)}), 400
        except Exception as e:
            logger.exception("Route error")
            return jsonify({"success": False, "message": "Internal error"}), 500
    return wrapper
```

**方案 4：使用状态管理模式**

```javascript
// static/js/state.js
class StateManager {
    constructor() {
        this._state = {};
        this._listeners = [];
    }
    
    get(key) { return this._state[key]; }
    set(key, value) {
        this._state[key] = value;
        this._notify(key, value);
    }
    
    _notify(key, value) {
        this._listeners
            .filter(l => l.key === key)
            .forEach(l => l.callback(value));
    }
}

// 视图与状态绑定
state.subscribe('can_input', (value) => {
    document.getElementById('can_disp').textContent = value || '未选择';
});
```
