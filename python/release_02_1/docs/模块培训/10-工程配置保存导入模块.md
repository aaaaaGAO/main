# 模块 10：工程配置保存及导入

## 本模块要培训的内容（讲师 checklist）

- [ ] 磁盘上 **三个配置文件** 各干什么：`Configuration.ini`、`FixedConfig.ini`、`filter_options.ini`
- [ ] **界面 JSON ↔ INI** 怎么映射（三域：`无前缀` / `c_` / `d_`）
- [ ] **自动保存** vs **点运行前再存一次**（`prepare_generation_config`）的区别
- [ ] **预设导入/导出**（另存为 INI、Tk 选文件）
- [ ] 管道格式：`path | Sheet1,Sheet2` 或 `path | *`（IO、ResetDid 等）
- [ ] **域 scoped 保存**：LR 自动保存不能覆盖 DTC 的 `uds.txt`；中央衍生文件同理
- [ ] FixedConfig 放什么：映射表路径、各模块**输出文件名**（改一处全局生效）
- [ ] **禁止跨域偷配置**：DTC 不从 LR 节读 IO；各生成器只读当前域节
- [ ] 客户常问：「改界面为什么立刻写文件？」「FixedConfig 和 Configuration 什么关系？」

## 先用大白话讲清楚：配置是「工具的记事本」

> 「您在网页里填的路径、勾选的等级、中央域串口参数，最终都要落到 **INI 文件**里，下次打开工具还能恢复。  
> **`Configuration.ini`** 是主笔记本：三域 Tab 的路径、筛选、输出目录都在这里。  
> **`FixedConfig.ini`** 是「很少改的设置」：关键字映射表在哪、生成的 Master.can 叫什么文件名。  
> **`filter_options.ini`** 只负责下拉框选项（等级 S/A/B…），不参与生成逻辑本身。」

**谁读写配置？**

| 操作 | 谁写 | 谁读 |
|------|------|------|
| 改界面任意项 | `StateConfigService.persist_state_config` | — |
| 点「开始运行」前 | `prepare_generation_config` 再存一次 | — |
| 页面加载 | — | `ConfigManager.load_ui_data` |
| 各生成器 | — | `GeneratorConfig` / `ConfigAccessor` |

## 三个配置文件（培训对照打开文件夹 `config/`）

| 文件 | 读写 | 主要内容 |
|------|------|----------|
| `Configuration.ini` | 读+写 | `[LR_REAR]` `[CENTRAL]` `[DTC]` 路径、筛选、输出、串口 JSON 等 |
| `FixedConfig.ini` | 读+写（保存时备份合并） | `[PATHS]` 映射表、各 `*_output_filename` |
| `filter_options.ini` | 只读 | `[FILTER_OPTIONS]` 等级/平台/车型列表 |

路径解析：`RuntimePathResolver` / `ProjectPaths` — **不** `os.chdir`，一律路径拼接。

## 逐文件讲解

### 1. `services/config_manager.py` — **核心** `ConfigManager`

**干什么**：INI 的「总编辑」——读、写、去重、格式化、UI 映射、触发衍生文件。

| 方法/函数 | 口语解释 |
|-----------|----------|
| `clean_duplicate_sections(config_path)` | 保存前清理重复节/重复键（行级） |
| `ConfigManager.from_base_dir(base_dir)` | 工厂：绑定工程根、解析 config 路径 |
| `reload_config_internal()` | 读 INI → 必要时 dedup 写回 |
| `load_ui_data()` | **INI → 前端 JSON**（三域所有字段） |
| `save_ui_data()` / `update_domain_config()` | 部分节写入 |
| `save_formatted_config(..., uds_domains=...)` | **格式化写回** + 可选写 uds/中央 sidecar |
| `build_formatted_config_text()` | 固定节顺序、`# [[group]]` 注释块 |
| `write_uds_files(only_domains=...)` | 写 `uds.txt`（**按域**，防 LR 覆盖 DTC） |
| `write_central_config_files()` | PowerRelay、Ignition、login 等 |
| `load_standard_domain_ui_fields` / `load_central_ui_json_fields` | 分域 UI 字段映射 |

**线程安全**：`write_lock = RLock()`，避免并发写坏 INI。

**保存时还会**：去掉废弃键、规范化 log_level、合并 FixedConfig 保留项。

---

### 2. `services/state_config_service.py` — 界面状态「总翻译官」

| 方法 | 口语解释 |
|------|----------|
| `persist_state_config(state, extra_write_path=...)` | 自动保存 / 预设：merge state → INI |
| `apply_state_to_config(state, cfg)` | 把前端扁平 JSON 写入 ConfigParser 对象 |
| `prepare_generation_config(state, uds_domain, skip_lr_rear)` | **运行前**：只更新当前域 + 相关节 |
| `get_lr_generation_flags(state)` 等 | 根据 state 里是否填 Excel 路径 → `run_can/run_did/...` |
| `sync_dtc_domain_inputs` / `sync_uart_comm_options` | DTC IO 管道、中央串口字段专项同步 |

**三域保存策略（必讲）**：

- 中央 Tab 保存：`skip_lr_rear=True`，**不覆盖** `[LR_REAR]`  
- DTC Tab 保存：同样不覆盖 LR  
- LR Tab 保存：只 scoped 写 LR 相关 UDS  

---

### 3. `services/config_service.py` — 薄封装

| 方法 | 口语解释 |
|------|----------|
| `build_lr_rear_section_data(payload)` | 脚本 API `/api/lr/config` 用：JSON → LR 节键值 |
| `save_lr_rear` / `get_lr_rear` | LR 节快捷读写 |
| `update_lr_rear_and_related` | 旧版 preset 路径，mutate 内存 cfg |

复杂格式化仍在 `ConfigManager`；本类给路由/脚本**短路径**更新。

---

### 4. `services/filter_service.py` — 筛选项

| 方法 | 口语解释 |
|------|----------|
| `parse_shaixuan_config(base_dir)` | 读 `filter_options.ini` → levels/platforms/models… |
| `parse_filter_option_value` | 拆逗号/中文逗号；非法分隔符拒绝 |

用于：页面加载下拉框 + CAN/XML 运行时校验允许值。

---

### 5. `services/config_constants.py` — **常量唯一来源**

所有节名、键名、UI state 键字符串**只在这里定义**；业务模块 import，禁止各处手写魔法串。

培训时演示：改一个 `STATE_KEY_*` 或 `OPTION_*` 如何全局生效。

---

### 6. `infra/config/` — 底层读 INI

| 模块 | 口语解释 |
|------|----------|
| `config_access.py` → `ConfigAccessor` | `read_main` / `read_fixed`；保留键大小写；容忍重复键 |
| `input_parser.py` → `split_input_lines` | 解析 `path \| sheets` 管道 |
| `__init__.py` | 对外 re-export：`read_config_if_exists`、`read_fixed_config` |

---

### 7. `services/derived_config_files_service.py`（点到为止）

中央域保存时写：`PowerRelayConfig.txt`、`IgnitionCycle.txt`、`login.txt` 等 sidecar。

## 典型流程（对着界面操作讲）

### 流程 A：打开工具加载配置

```
GET /api/load_config
  → ConfigManager.load_ui_data()
  → 返回 { can_input, c_uart, d_io_excel, levels, ... }
  → 前端 initFromConfig 填 DOM
```

### 流程 B：改一项自动保存

```
前端 autoSaveConfig
  → POST /api/auto_save_config { data: collectCurrentState() }
  → StateConfigService.persist_state_config
  → ConfigManager.save_formatted_config(uds_domains=[当前影响的域])
  → Configuration.ini 更新
```

### 流程 C：点「开始运行」

```
GenerationRouteService.execute_from_payload
  → prepare_generation_config（再存一次，确保与界面一致）
  → get_*_generation_flags
  → TaskOrchestrator...
```

### 流程 D：导出/导入预设

```
save_preset: Tk 另存为 → persist_state_config(extra_write_path=所选.ini)
import_preset: Tk 打开 → ConfigManager(所选).load_ui_data → 回填 → 同步主 INI
```

## 管道格式（培训白板示例）

```
input/IO_mapping.xlsx | *
```

## 客户常问问题（备答）

| 问题 | 建议回答 |
|------|----------|
| 为什么改界面就写 INI？ | 防止关浏览器丢配置；下次打开即恢复 |
| FixedConfig 要手改吗？ | 一般开发/部署时改映射表路径；界面改路径写 Configuration |
| LR 和 DTC 会互相覆盖吗？ | 自动保存按域 scoped；中央/DTC 保存不动 LR 节 |
| filter_options 和 Configuration 区别？ | 前者只供**下拉选项**；选中结果写在 Configuration 的 case_levels 等 |
| 预设和主 INI 关系？ | 预设是**额外副本**；导入后会同步回主 Configuration.ini |

## 演示建议

1. 打开 `config/Configuration.ini`，对照三域节名  
2. 界面改一个路径 → 看 INI 对应键变化  
3. 中央 Tab 保存 → 确认 `[LR_REAR]` 未被清空  
4. 导出预设 → 用记事本打开预设 INI  
5. 打开 FixedConfig 看 `mapping_excel`、`output_filename`  

**预计时长**：1.5～2h
