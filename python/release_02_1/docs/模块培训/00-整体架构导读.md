## 先用大白话：这个工具干什么

> 「测试同事在 Excel 里写用例和配置表，本工具读取这些 Excel 和 INI 配置，**批量生成** CAPL 的 `.can`、`.cin`、诊断 txt、SOA 节点、UART 配置、测试模块 XML 等文件。  
> 您通过 **浏览器** 选路径、点「开始运行」；真正干活的是本机跑的 **Python 程序**（双击 EXE 或 `python app.py`）。」

## 分层结构（必画白板）

```
┌─────────────────────────────────────────┐
│  浏览器  templates/ + static/js/         │  ← 您看到的界面
└─────────────────┬───────────────────────┘
                  │ HTTP JSON (/api/...)
┌─────────────────▼───────────────────────┐
│  web/routes/*                            │  ← 「接电话」：转给 Service
└─────────────────┬───────────────────────┘
                  │
┌─────────────────▼───────────────────────┐
│  services/*  ConfigManager、编排…        │  ← 存配置、安排任务
└─────────────────┬───────────────────────┘
                  │
┌─────────────────▼───────────────────────┐
│  TaskOrchestrator → generators/capl_*    │  ← 读 Excel、写交付文件
└─────────────────┬───────────────────────┘
                  │
┌─────────────────▼───────────────────────┐
│  core/*  StepParser、IO 翻译、日志        │  ← 共用内核
└─────────────────────────────────────────┘
                  │
         config/*.ini  （Configuration 等）
```

**记住**：JavaScript **不**读 Excel、**不**写 .can；只发 JSON。

## 一键生成主链路

```
用户点击「开始运行」
  → 前端 collectCurrentState() 收集界面
  → POST /api/generate | generate_central | generate_dtc
  → GenerationRouteService：
       ① 把界面状态写入 Configuration.ini
       ② 根据填了哪些 Excel 决定 run_can、run_did、run_uart…
  → TaskOrchestrator 按域顺序调用各 generators
  → 返回 success / message → 前端 alert
  → log/log_时间戳/ 留下完整记录
```

详细 GUI 链路见 [01-前端GUI模块.md](./01-前端GUI模块.md)。

## 三域与配置节

| 界面 Tab | INI 节 | 典型独有任务 |
|----------|--------|--------------|
| 左右后 | `[LR_REAR]` | DID、ResetDid、CIN、SOA、CAN、XML |
| 中央 | `[CENTRAL]` | **UART**、SOA、CAN、XML |
| DTC | `[DTC]` | IO Mapping、DID、ResetDid、CIN、SOA、CAN、XML |

**原则**：各域只读**自己的节**，不从别的 Tab「偷」配置（客户条款明确要求）。

---

## 三域编排顺序（`services/task_orchestrator.py`）

| 域 | 子任务顺序 |
|----|------------|
| 左右后 `[LR_REAR]` | did_config → did_info → cin → soa → can → xml |
| 中央 `[CENTRAL]` | **uart** → soa → can → xml |
| DTC `[DTC]` | did_config → did_info → cin → soa → can → xml |

### 三个关键约定（必背）

1. **CIN 在 CAN 之前** — Master.can 要 `#include` 刚生成的 `.cin`  
2. **UART 仅中央域** — 左右后/DTC 编排里没有 uart 步  
3. **IO Mapping 不单独成步** — 嵌在 CAN/CIN 的 StepParser 里（模块 2）
